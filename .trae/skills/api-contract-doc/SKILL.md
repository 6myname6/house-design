# 接口文档编写技能（筑梦家）

接口文档是**前后端关于 HTTP 接口的开发约定**，不是开发记事本。只写：请求、响应、错误、前端必须遵守的行为约束。

## 一、写之前必做（防止文档与代码脱节）

1. 先读 `docs/接口文档.md` 开头的「通用约定」，沿用其鉴权、统一响应、错误码、分页/上传/时间规则，不要在单个接口里重复这些公共内容。
2. 以**后端代码为唯一事实来源**，按顺序核对：
   - Controller：HTTP 方法、完整路径（含 `/api` 前缀）、`@RequestMapping`、鉴权（默认需要，免鉴权看 `config/WebConfig.java` 的 excludePathPatterns）。
   - 请求 DTO / `@RequestParam` / 表单字段：字段名、类型、是否必填、校验注解（`@NotBlank/@Size/@Pattern` 等）。
   - 响应 DTO：字段名、类型、可空性、嵌套结构。
   - Service/Controller 中 `new BusinessException(code, msg)` 的真实错误码与文案。
3. 字段名、类型、枚举值、错误文案必须逐字来自代码，**禁止杜撰**；拿不准就读代码，不要猜。
4. 不写入服务端内部实现（Redis key、线程池、SQL、第三方 SDK 踩坑、Bean 装配等）、开发进度标记、日期流水、未来规划。

## 二、每个接口的固定三段式格式

接口编号 `x.y`，子标题 `x.y.1 基本信息 / x.y.2 请求参数 / x.y.3 响应数据`。

### 基本信息（引用块）

```markdown
#### x.y.1 基本信息

> 请求路径：/api/xxx
>
> 请求方式：GET|POST|PUT|DELETE
>
> 接口描述：一句话说明用途与关键行为
>
> 是否鉴权：是|否
```

### 请求参数

- 先写 `参数格式：application/json | queryString | 路径参数 | multipart/form-data`。
- 参数说明表四列：`参数名 | 类型 | 是否必须 | 备注`，备注写长度/格式/默认值/与其他字段的联动约束。
- 必须给「**请求参数样例**」（无参接口写"无"并省略样例）：
  - JSON：可直接发送的请求体。
  - queryString：`/api/xxx?a=1&b=2`。
  - 路径参数：`/api/xxx/10`。
  - multipart：给出 boundary 形式的表单结构示意。
- 路径参数 + JSON body 同时存在时，路径参数与请求体分两张表。

### 响应数据

- 参数说明表必须以统一包装开头：`code`（number，必须，200 成功）、`message`（string，非必须）、`data`（类型按实际）。
- 嵌套字段用 `|- 字段名` 缩进表示；数组写 `object[]`，元素结构在备注里指向对应「数据结构」小节。
- 必须给「**响应数据样例**」：完整的 `{code, message, data}` JSON，示例 ID/时间/图片地址用示意值，时间格式 `yyyy-MM-dd'T'HH:mm:ss`。
- 同一接口成功响应有多种形态时（如 AI 对话纯文本返回对象、图文返回字符串），分别给样例并说明触发条件。
- 失败响应不要逐个贴样例：统一形态是 `{"code":错误码,"message":"提示","data":null}`，在接口末尾用一行「常见失败：code 文案；code 文案」列出该接口特有的业务错误即可。

## 三、文档组织与维护规则

- 章节按业务域分组：认证 / 风格 / 项目 / 效果生成 / 装修小圈 / 文件 / AI；新增接口归入对应域并顺延编号，更新同域「数据结构」小节。
- 可复用结构（Project、Post、Comment、Generation 等）集中放在该域的「x.n 数据结构」里用字段表定义，接口处只引用、不重复展开。
- 特殊的内嵌数据（如 `sceneConfig` 这种 JSON 字符串里的深层结构）放文末「附录」。
- 新增/修改接口后同步检查：速查性质的公共规则、相关数据结构表、跨接口引用编号是否一致。

## 四、本项目关键事实（改代码后若变化需同步修订）

- 统一包装 `{ code, message, data }`：**业务成功与业务失败 HTTP 都是 200**，以 body 的 code 为准；仅鉴权失败返回 HTTP 401。
- 业务码：200 成功 / 400 参数或业务错误 / 401 未登录或凭证无效 / 404 资源不存在或不属于当前用户（越权也返 404）/ 409 冲突 / 429 频控 / 500 内部错误 / 503 依赖服务不可用。
- 免鉴权接口：`/api/auth/register`、`/api/auth/login`、`/api/auth/sms/code`、`/api/auth/sms/login`、`GET /files/**`。
- 鉴权头：`Authorization: Bearer <token>`，JWT 7 天有效。
- 分页：`pageNum`（从 1 开始，默认 1）、`pageSize`（默认 20，最大 50，越界自动收敛）；响应 `{ total, records }`。
- 上传：multipart/form-data，jpg/jpeg/png/gif/webp，单文件 ≤20MB；业务接口中的图片传"已上传获得的本系统图片 URL"，不传 base64/外链。
- 时间字段：字符串 `yyyy-MM-dd'T'HH:mm:ss`。

## 五、完成后自检

- [ ] 路径、方法、鉴权与 Controller/WebConfig 一致。
- [ ] 请求字段（名/类型/必填/约束）与 DTO 校验注解一致。
- [ ] 响应字段与响应 DTO 一致，可空字段有标注，嵌套用 `|-` 展开。
- [ ] 每个接口都有请求样例（无参除外）和完整响应样例。
- [ ] 错误码与文案来自真实 `BusinessException`，没有杜撰。
- [ ] 无内部实现、进度标记、日期流水、未来规划等"记事本"内容。
