# 筑梦家 · 产品文档

> 上传房屋设计图，由 AI 生成可交互的**3D 施工效果**（独立的三维动态网页）。
> 技术栈：**Spring Boot 3 + MySQL 8 + Vue 3 + Three.js + 智谱 CogView 文生图**。

---

## 1. 产品定位

「筑梦家」是一个面向装修业主 / 设计师的房屋装修效果可视化平台。用户上传户型平面图或设计图，平台调用 AI 生成对应装修风格的**写实效果图**与**可交互的 3D 漫游场景**，让用户在"施工前"就能身临其境地看到装修完成后的样子，并能在社区分享交流。

产品核心价值：

- **零门槛出图**：无需建模软件，上传一张图即可生成多房间写实效果图。
- **可交互漫游**：3D 场景支持旋转、缩放、平移、自动环视；照片模式支持 VR 式缓慢扫视。
- **风格可换**：内置 5 种主流装修风格，一键切换不同色调与软装氛围。
- **服务可插拔**：内置 `mock` 程序化生成（免外部依赖），也可接入智谱真实文生图，无需改动业务代码。
- **社区互动**：「装修小圈」发帖、点赞、评论，沉淀装修灵感。

## 2. 核心功能

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 账号 | 注册 / 登录 / 个人信息 | JWT 鉴权，密码 BCrypt 加密；支持修改昵称与头像 |
| 项目 | 创建 / 列表 / 详情 / 删除 | 一个项目 = 一份设计图 + 一个装修风格；上传图可为户型图 / CAD 导出 / 手绘稿 |
| 生成 | 一键生成 3D 效果 | 异步任务；支持状态轮询；生成成功后可查看 3D 效果 |
| 3D 查看 | 漫游 / 旋转 / 缩放 / 平移 / 自动扫视 | 真实 AI 产出为「多房间写实照片 + VR 式扫视」；mock 产出为「程序化 3D 户型」 |
| 社区 | 发帖 / 列表 / 我的帖子 / 点赞 / 评论 | 扁平评论结构；图片可上传至平台后引用 URL |
| 文件 | 通用上传 | 头像、帖子图片等统一走 `/api/files/upload` |

## 3. 用户角色

当前版本为**单角色**（普通用户），所有登录用户权限一致：

- 仅可访问/操作**自己**的项目、生成任务、帖子与点赞（后端基于 `userId` 做归属校验）。
- 鉴权失败（401）时前端自动登出并跳转登录页。

## 4. 典型使用流程

```
注册 / 登录
   │
   ▼
首页 / 项目列表 ──► 新建项目（填名称、选风格、上传设计图）
   │
   ▼
项目详情 ──► 点击「生成 3D 施工效果」
   │            （后端创建 PENDING 任务 → 异步处理 → 轮询状态）
   ▼
生成中（轮询 PENDING → PROCESSING → SUCCESS）
   │
   ▼
查看 3D 效果（多房间写实照片 + VR 式扫视 / 程序化 3D 户型）
   │
   ▼
（可选）到「装修小圈」分享效果图、浏览他人帖子、点赞评论
```

### 4.1 生成模式说明

后端根据 `app.ai.provider` 选择实现（`ImageTo3DServiceFactory`）：

| provider | 行为 | 产物 |
| --- | --- | --- |
| `mock`（默认） | 内置程序化户型重建，无需外部服务 | `sceneConfig`（type=`procedural-apartment`），前端用 Three.js 重建可交互 3D 户型；无 URL |
| `zhipu` | 调用智谱 CogView 文生图（需 `api-key`） | 每个房间生成一张写实照片（1344×768，约 16:9），落盘后写入 `panoramaUrl`，`sceneConfig`（type=`photo-tour`）记录多房间映射 |

> 未配置 `api-key` 时，即使 `provider=zhipu` 也会因"无 Key"报错，需显式配置或回退 `mock`。

## 5. 装修风格

`DesignStyle` 枚举，5 种内置风格，每种自带调色板（`wall/floor/wood/fabric/accent`）与英文贴图提示（供真实 AI 引导）。非法/空风格自动回退「现代简约」。

| code | 名称 | 主色调 |
| --- | --- | --- |
| `modern-minimalist` | 现代简约 | 中性灰白、干净直线、哑光 |
| `cream-french` | 奶油轻法式 | 暖象牙米、柔布、拱形、复古金 |
| `italian-luxury` | 现代/意式极简轻奢 | 高级灰、深木、大理石、香槟金 |
| `new-chinese` | 轻量化新中式 | 胡桃木、墨灰、青瓷、黄铜 |
| `log-wood` | 原木风 | 橡木、米麻、绿植、温馨明亮 |

## 6. 技术架构

### 6.1 整体架构

```
┌─────────────┐      HTTP / JSON       ┌──────────────────────────┐
│  Vue 3 SPA   │  ───────────────────►  │   Spring Boot 3 后端       │
│ (Vite:5173)  │  ◄───────────────────  │   (Tomcat:8080)           │
└─────────────┘      /api, /files        └────────────┬─────────────┘
                                                      │
                                          ┌───────────┼────────────┐
                                          ▼           ▼            ▼
                                      MySQL 8    本地存储(storage)  智谱 CogView API
                                     (JPA)      (设计图/全景图)    (文生图)
```

- **前端**：Vue 3 + Vite + Pinia + Vue Router + Element Plus + Three.js；Axios 封装（`baseURL=/api`，Vite 代理转发到 `:8080`）。
- **后端**：Spring Boot 3 + Spring Data JPA + Spring WebFlux `WebClient`（调智谱）；CORS 放行、静态资源 `/files/**` 映射至 `storage/` 目录。
- **存储**：MySQL 存结构化数据；本地文件系统存上传图与生成图（默认 `./storage`，可通过 `app.storage.location` 配置）。

### 6.2 关键包结构

```
backend/src/main/java/com/housedesign/
├── config/      # AppProperties、WebConfig、AsyncConfig
├── common/      # Result（统一响应）、BusinessException、GlobalExceptionHandler
├── controller/  # Auth / Project / Generation / Community / File
├── dto/         # AuthDtos / ProjectDtos / GenerationDtos / CommunityDtos
├── entity/      # User / DesignProject / GeneratedModel / Post* / DesignStyle / GenerationStatus
├── security/    # JWT、拦截器、参数解析器（@CurrentUserId）
├── service/     # UserService / ProjectService / GenerationService / GenerationProcessor / CommunityService / FileStorageService
└── service/ai/  # ImageTo3DService 接口 + MockImageTo3DService + ZhipuImageService + Factory
```

### 6.3 生成状态机（`GenerationStatus`）

```
PENDING ──► PROCESSING ──► SUCCESS
                  │
                  └──────► FAILED（errorMessage 记录原因）
```

- `PENDING`：任务已创建，等待异步处理。
- `PROCESSING`：异步线程池中正在生成（调 AI / 程序化重建）。
- `SUCCESS`：生成完成，`panoramaUrl` / `sceneConfig` 等字段已填充。
- `FAILED`：失败，`errorMessage` 含原因（如智谱 429 限流/额度不足、Key 无效等）。

## 7. 3D 查看器（`Viewer3D.vue`）

| 模式 | 触发条件 | 表现 |
| --- | --- | --- |
| 照片漫游（photo-tour） | `sceneConfig.type=photo-tour`（智谱真实出图） | 按真实比例平面展示，VR 式水平扫视动画；底部缩略图切换房间；「自动旋转」可开关 |
| 程序化 3D（procedural-apartment） | `sceneConfig.type=procedural-apartment`（mock） | Three.js 重建户型，自由旋转/缩放/平移、线框模式、自动旋转、光照调节、720° 球体内贴图 |

```yaml

  ai:
    provider: zhipu
    api-key: "你的智谱 Key"
    base-url: "https://open.bigmodel.cn/api/paas/v4"
    image-model: cogview-4
```

## 9. 已知约束与后续规划

- **照片模式为写实照片而非真 360° 全景**：文生图本质是单张透视照片，无法像球面那样真实转动；VR 扫视为 CSS 模拟的转头视差（轻微裁切边缘）。
- **房间布局固定**：当前默认生成「客厅/主卧/厨房/卫生间」4 个房间，暂不支持自定义户型。
- **社区评论为扁平结构**：暂不支持楼中楼回复。
- 若需真 720° 实景漫游，需接入专门产出等距柱状全景图的 360 全景服务。
