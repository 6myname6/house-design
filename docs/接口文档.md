## 通用约定

> 接口基址：`/api`（开发环境由 Vite 代理到 `http://localhost:8080`）；图片由后端上传至阿里云 OSS 后返回**公网绝对 URL**（形如 `https://mybucket0100.oss-cn-beijing.aliyuncs.com/{dir}/{uuid}.ext`），前端直接使用，无 `/files` 本地路径。
>
> 编码：请求与响应均为 `UTF-8`；JSON 接口 `Content-Type: application/json`。

### 鉴权

除登录、注册、发送验证码、验证码登录四个接口外，其余接口都需要在请求头携带 JWT：

```
Authorization: Bearer <token>
```

token 由登录接口返回，有效期 7 天。未携带 / 非法 / 过期 / 已登出的 token 返回 HTTP 401，响应体：

```json
{ "code": 401, "message": "登录已过期，请重新登录", "data": null }
```

> **单端互踢（A-12）**：同一账号在其他设备（浏览器）重新登录后，旧设备 token 立即失效——后续请求返回 HTTP 401，`message` 为「账号已在其他地方登录，请重新登录」。实现：Redis `login:active:{userId}` 存当前唯一有效 token 的 SHA-256 指纹，登录覆盖、拦截器比对。

### 统一响应结构

所有接口统一返回：

| 参数名     | 类型                                      | 是否必须 | 备注                   |
| ------- | --------------------------------------- | ---- | -------------------- |
| code    | number                                  | 必须   | 响应码，200 代表成功，其余代表失败  |
| message | string                                  | 非必须  | 提示信息；失败时为可直接展示给用户的原因 |
| data    | object / array / string / number / null | 非必须  | 返回的数据                |

- 业务成功与业务失败的 **HTTP 状态码都是 200**，以响应体 `code` 为准；只有鉴权失败返回 HTTP 401。
- 业务错误码：400 参数 / 业务错误，401 未登录或凭证无效，404 资源不存在或不属于当前用户，409 操作冲突，429 触发频率限制，500 服务器内部错误，503 依赖服务暂不可用。
- 失败响应统一为 `{ "code": 错误码, "message": "提示", "data": null }`，下文只给成功响应样例。

### 通用规则

- 分页参数：`pageNum`（从 1 开始，默认 1）、`pageSize`（默认 20，最大 50，越界自动收敛）；分页响应为 `{ total, records }`。
- 文件上传：`multipart/form-data`，仅接受 jpg / jpeg / png / gif / webp，单文件不超过 20MB。
- 时间字段：字符串，格式 `yyyy-MM-dd'T'HH:mm:ss`，如 `"2026-10-14T10:00:00"`。
- 业务接口中的图片一律传**已通过上传接口获得的本系统图片 URL**。

## 1. 认证管理

### 1.1 注册

#### 1.1.1 基本信息

> 请求路径：/api/auth/register
>
> 请求方式：POST
>
> 接口描述：新用户注册（用户名 + 密码 + 邮件验证码），联系标识为**邮箱**（先调 1.6 发送邮箱验证码）。成功返回新用户 ID，之后需调用登录接口换取令牌；5 秒内禁止重复提交
>
> 是否鉴权：否

#### 1.1.2 请求参数

参数格式：application/json

参数说明：

| 参数名      | 类型     | 是否必须 | 备注                                     |
| -------- | ------ | ---- | -------------------------------------- |
| username | string | 必须   | 用户名，3–32 字符                            |
| password | string | 必须   | 密码，8–32 字符                             |
| code     | string | 必须   | 验证码（邮件验证码）             |
| email    | string | 必须   | 邮箱，长度 ≤ 128（A-11 新增）     |

请求参数样例：

```json
{
  "username": "zhangsan",
  "email": "zhangsan@example.com",
  "code": "483920",
  "password": "12345678"
}
```

#### 1.1.3 响应数据

参数格式：application/json

参数说明：

| 参数名     | 类型     | 是否必须 | 备注     |
| ------- | ------ | ---- | ------ |
| code    | number | 必须   | 200 成功 |
| message | string | 非必须  | 提示信息   |
| data    | number | 非必须  | 新用户 ID |

响应数据样例：

```json
{
  "code": 200,
  "message": "success",
  "data": 52
}
```

常见失败：400 验证码错误或已过期 / 用户名已被占用 / 邮箱已注册；409 操作太频繁，请稍后再试。

### 1.2 账号登录

#### 1.2.1 基本信息

> 请求路径：/api/auth/login
>
> 请求方式：POST
>
> 接口描述：用户名 + 密码登录，成功返回 JWT 令牌
>
> 是否鉴权：否

#### 1.2.2 请求参数

参数格式：application/json

参数说明：

| 参数名      | 类型     | 是否必须 | 备注  |
| -------- | ------ | ---- | --- |
| username | string | 必须   | 用户名 |
| password | string | 必须   | 密码  |

请求参数样例：

```json
{
  "username": "zhangsan",
  "password": "12345678"
}
```

#### 1.2.3 响应数据

参数格式：application/json

参数说明：

| 参数名     | 类型     | 是否必须 | 备注     |
| ------- | ------ | ---- | ------ |
| code    | number | 必须   | 200 成功 |
| message | string | 非必须  | 提示信息   |
| data    | string | 非必须  | JWT 令牌 |

响应数据样例：

```json
{
  "code": 200,
  "message": "success",
  "data": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiI1MiJ9.签名部分略"
```

常见失败：400 用户名或密码错误；429 连续失败过多，账号 / IP 临时锁定（message 含剩余锁定时间）。

### 1.3 获取当前用户信息

#### 1.3.1 基本信息

> 请求路径：/api/auth/me
>
> 请求方式：GET
>
> 接口描述：查询当前登录用户的信息
>
> 是否鉴权：是

#### 1.3.2 请求参数

无

#### 1.3.3 响应数据

参数格式：application/json

参数说明：

| 参数名             | 类型     | 是否必须 | 备注                                                  |
| --------------- | ------ | ---- | --------------------------------------------------- |
| code            | number | 必须   | 200 成功                                              |
| message         | string | 非必须  | 提示信息                                                |
| data            | object | 非必须  | 当前用户信息                                              |
| \|- id          | number | 非必须  | 用户 ID                                               |
| \|- username    | string | 非必须  | 用户名                                                 |
| \|- nickname    | string | 非必须  | 昵称，未设置为 null                                        |
| \|- avatar      | string | 非必须  | 头像 URL，未设置为 null                                    |
| \|- maskedEmail | string | 非必须  | 掩码邮箱（A-5 新增），如 `3***@qq.com`；未绑定为 null              |

响应数据样例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 52,
    "username": "zhangsan",
    "nickname": "张三",
    "avatar": null,
    "maskedEmail": null
  }
}
```

### 1.6 发送邮箱验证码

#### 1.6.1 基本信息

> 请求路径：/api/auth/email/code
>
> 请求方式：POST
>
> 接口描述：发送登录 / 注册邮箱验证码（QQ 邮箱 SMTP 真实发信，HTML 邮件）；验证码只通过邮件送达，不随接口返回，有效期 5 分钟；频控规则：60 秒间隔、同邮箱 10 封/24h、同 IP 20 封/24h

> 是否鉴权：否

#### 1.6.2 请求参数

参数格式：application/json

| 参数名   | 类型     | 是否必须 | 备注                                  |
| ----- | ------ | ---- | ----------------------------------- |
| email | string | 必须   | 邮箱，长度 ≤ 128                         |
| scene | string | 必须   | `login`（邮箱须已注册）/ `register`（邮箱须未注册） |

请求参数样例：

```json
{
  "email": "zhangsan@example.com",
  "scene": "register"
}
```

#### 1.6.3 响应数据

参数格式：application/json

参数说明：

| 参数名     | 类型     | 是否必须 | 备注       |
| ------- | ------ | ---- | -------- |
| code    | number | 必须   | 200 成功   |
| message | string | 非必须  | 提示信息     |
| data    | null   | 非必须  | 固定为 null |

响应数据样例：

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

常见失败：400 邮箱格式错误 / 非法场景 / 邮箱注册状态与场景不符；429 发送过频或超当日上限；503 邮件服务暂不可用（SMTP 配置缺失或发信失败，删频控占位可立即重试）。

### 1.8 发送修改密码验证码（A-5，需登录）

#### 1.8.1 基本信息

> 请求路径：/api/auth/password/code
>
> 请求方式：POST
>
> 接口描述：向**当前登录用户本人绑定**的邮箱发送修改密码验证码；收件地址由后端按 token 中的 userId 查库决定，不接受请求体传入邮箱。验证码 5 分钟有效；60 秒发送间隔；10 次/24h
>
> 是否鉴权：是

#### 1.8.2 请求参数

参数格式：application/json

参数说明：

| 参数名     | 类型     | 是否必须 | 备注                                              |
| ------- | ------ | ---- | ----------------------------------------------- |
| channel | string | 必须   | 验证通道：`email`（绑定的邮箱，真实邮件） |

请求参数样例：

```json
{
  "channel": "email"
}
```

#### 1.8.3 响应数据

同通用成功响应，data 为 null。

常见失败：400 非法通道 / 当前账号未绑定邮箱；401 未登录；429 发送过频（含剩余秒数）或超当日上限。

### 1.9 修改密码（A-5，需登录）

#### 1.9.1 基本信息

> 请求路径：/api/auth/password/change
>
> 请求方式：POST
>
> 接口描述：凭修改密码验证码设置新密码；验证码一次性失效，连续输错 5 次锁定 300 秒；**成功后当前 token 立即加入黑名单**，前端须清登录态并跳转登录页用新密码重登
>
> 是否鉴权：是

#### 1.9.2 请求参数

参数格式：application/json

参数说明：

| 参数名         | 类型     | 是否必须 | 备注                       |
| ----------- | ------ | ---- | ------------------------ |
| channel     | string | 必须   | 固定 `email`，须与发码通道一致 |
| code        | string | 必须   | 6 位验证码                   |
| newPassword | string | 必须   | 新密码，8–32 字符              |

请求参数样例：

```json
{
  "channel": "email",
  "code": "483920",
  "newPassword": "new-pass-123"
}
```

#### 1.9.3 响应数据

data 为 null 的通用成功响应，message 为「密码修改成功，请重新登录」。

常见失败：400 非法通道 / 验证码错误或已过期 / 新密码长度 8-32；401 未登录；429 验证码错误次数过多，请重新获取验证码。改密成功后下一请求起当前 token 返回 401。

> 是否鉴权：是

#### 1.10.2 请求参数

| 参数名   | 类型     | 是否必须 | 备注               |
| ----- | ------ | ---- | ---------------- |
| email | string | 必须   | 待绑定的新邮箱，长度 ≤ 128 |

请求参数样例：

```json
{
  "email": "newmail@qq.com"
```

### 7.1 AI 对话

#### 7.1.1 基本信息

#### 7.1.2 请求参数

参数格式：application/json

参数说明：

| 参数名            | 类型        | 是否必须 | 备注                                     |
| -------------- | --------- | ---- | -------------------------------------- |

| images         | string\[] | 非必须  | 图片 URL 列表（须为本系统上传所得地址），最多 4 张          |
| conversationId | string    | 非必须  | 会话 ID，最长 64；首轮不传，非空时必须为标准 UUID，后续轮原样带回 |

请求参数样例：

纯文本首轮：

```json
{
  "question": "现代简约风格怎么搭配主色调？"
}
```

纯文本追问：

```json
{
  "question": "那预算 5 万怎么落地？",
  "conversationId": "9f2c1a7e-3b2d-4c8e-9a1f-0c2d4e6f8a01"
}
```

图文提问（同样携带会话 ID，参与多轮记忆）：

```json
{
  "question": "这张客厅效果图是什么风格？",
  "images": ["https://mybucket0100.oss-cn-beijing.aliyuncs.com/uploads/a3f9c1e2.png"],
  "conversationId": "9f2c1a7e-3b2d-4c8e-9a1f-0c2d4e6f8a01"
}
```

#### 7.1.3 响应数据

参数格式：application/json

所有链路（纯文本 / 图文 / 纯图）响应结构统一，`data` 均为对象。

参数说明：

| 参数名                | 类型     | 是否必须 | 备注                    |
| ------------------ | ------ | ---- | --------------------- |
| code               | number | 必须   | 200 成功                |
| message            | string | 非必须  | 提示信息                  |
| data               | object | 非必须  | 对话结果                  |
| \|- conversationId | string | 必须   | 会话 ID（首轮由后端生成，后续原样返回） |
| \|- answer         | string | 必须   | AI 回答（Markdown 文本）    |

响应数据样例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "conversationId": "9f2c1a7e-3b2d-4c8e-9a1f-0c2d4e6f8a01",
    "answer": "现代简约风格通常以中性色为主……"
  }
}
```

纯图场景后端按「请解释这张图」作为提问处理，响应结构相同。

> 失败语义：模型调用失败（限流 / 超时 / 上游故障）返回 503 时，**本轮提问不会写入会话记忆**，前端重试不会产生重复消息或上下文断裂。

常见失败：400 输入不能为空 / 非法会话标识 / 图片地址不能为空 / 仅允许使用已上传的图片地址（images 必须是上传接口返回的 OSS URL，其他域名一律拒绝）；503 对不起，当前AI服务繁忙，请稍后再试\~。

## 8. 知识库

> 本域用于管理 AI 检索所依据的知识文档。**入库是异步的**：创建接口只建记录并立即返回，解析、切块与向量化由服务端后台推进，前端需凭 `documentId` 轮询详情接口直到状态终态。
>
> 状态流转：`PENDING`（待入库）→ `PARSING`（解析中）→ `INDEXING`（切块与向量化中）→ `READY`（可检索）/ `FAILED`（失败，`errorMessage` 给出原因）。
>
> 可见性：`PUBLIC` 文档所有用户可检索；`PRIVATE` 文档仅创建者可见、可检索。
>
> **接口状态：8.1–8.5 均为「契约已定、待实现」。** 实现时字段名、类型、枚举取值与错误文案一律以本文档为准，不得增删或改写；实现并验证通过后再删除本段。

### 8.4 数据结构

**KbDocument（知识库文档）**

| 字段 | 类型 | 是否必须 | 说明 |
| ---- | ---- | ---- | ---- |
| id | number | 必须 | 文档 ID |
| title | string | 必须 | 文档标题；不传时由文件名或默认值补齐 |
