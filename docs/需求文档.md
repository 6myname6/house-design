## 1. 产品概述

### 1.1 背景与目标
面向装修业主与设计师，提供"上传房屋设计图 → AI 生成可交互 3D 施工效果 → 社区分享交流"的一站式可视化平台。核心目标是让用户在施工前就能身临其境地预览装修完成效果，降低决策与沟通成本。

### 1.2 价值主张
- 零门槛出图：上传一张图即可生成写实效果图。
- 可交互漫游：3D 场景支持旋转/缩放/平移/自动环视。
- 风格可换：内置 5 种主流装修风格。
- 生成直连厂商 API：单厂商直连，直接调用阿里云百炼万相文生图（无内置 mock 兜底）。
- 社区互动：装修灵感沉淀与分享。

### 1.3 技术栈
Spring Boot 3 + MySQL 8 + Vue 3 + 阿里云百炼（qwen3-vl-plus 理解 / wanx2.1-t2i-turbo 生图）；图片统一持久化到阿里云 OSS。登录限流使用 Redis（已实现，见 S-3）；邮箱验证码登录基于 Redis（已实现，见 A-11）；退出登录的 token 黑名单基于 Redis（已实现 2026-10-07，见 A-9 / S-4）；AI 多模态对话使用 LangChain4j 接入百炼 qwen3-vl-plus（见 §3.7 / §10.4）。

## 6. 关键业务流程

### 6.1 核心闭环
```
注册/登录 → 新建项目(传图+选风格) → 发起生成(异步) → 轮询状态
→ 查看 3D 效果 → (可选)社区发帖/浏览/点赞/评论
```

### 6.2 生成状态机
```
PENDING ──► PROCESSING ──► SUCCESS
                  │
                  └──────► FAILED (errorMessage 记录原因)
```
失败原因需覆盖：上游 429 限流（指数退避重试）、额度不足、Key 无效、`BAILIAN_API_KEY` 未配置等，均写入 `errorMessage`（无 Key 直接报错提示，不回退 mock）。

## 7. 验收标准（本期交付基线）

1. 单用户可完整走通"上传→生成→查看→分享"闭环。
2. 未登录访问受保护接口返回 401，前端自动登出。
3. 用户仅能访问自己的资源，越权返回 403/404。
4. 上传文件被类型与大小校验拦截非法文件。
5. 列表接口支持分页且不随数据量线性劣化。
6. 密钥不落库、不进版本库（已通过环境变量 + .gitignore 约束）。
7. （A-9）点击退出登录后前端清空本地登录态并跳转登录页；用登出前的旧 token 再调任意受保护接口必须返回 401（服务端黑名单生效），重新登录获得的新 token 不受影响。

## 9. 已知约束
- 照片模式为写实宽幅透视照片（2:1），非真 360° 球面全景（当前生图模型无原生 equirectangular 模式，V-3 待实验）。
- 房间布局由 AI 视觉模型识别户型图得出（上限 6 个主要空间），不再固定 4 间；识别结果受户型图清晰度影响，手绘/模糊图可能失败；面积为估算量级，非精确丈量。
- 圆点热点方位为后端按 AI 给出的门方位规则化映射（左/中/右三档），不保证与画面中门的像素位置精确重合。
- 生成链路重试策略（2026-10-13 加固）：仅 429/5xx/超时/网络 IO 重试（尊重 Retry-After，退避 2s→4s），400/401/403 立即失败；「生图+下载」同一重试单元；AI 图片下载有 20MB 缓冲/字节双上限与 image/* 类型校验；用户文本经清洗与分隔符包裹收敛提示词注入。
- 评论已支持两级楼中楼（`parent_id`），暂不支持更深层级。
- 图片统一持久化到阿里云 OSS 公共读 bucket（唯一存储后端，启动 fail-fast 校验密钥），返回公网 URL，多实例部署无需共享磁盘。
- 生成模块（G）与照片漫游（V）已上线：AI 视觉识别户型 → 逐房间写实生图两阶段 + `Viewer3D.vue` 全屏漫游（2026-10 实测通过）。

## 10. 新增需求（2026-09-14）

### 10.1 登录页背景轮播（A-8）

### 10.2 帖子详情页（C-12）

- **验收**：从「我的发布」点击可进入详情；他人点赞/评论可见；本人点赞/评论即时生效并回显。

### 10.4 AI 设计助手：多模态对话（AI，2026-09-18 新增）

- **目标**：用户可向 AI 咨询装修问题（风格识别、配色、建材、预算等），并能**发送图片**让 AI 结合画面回答（如"这张图是什么风格""我家户型能不能这样装"）。
- **技术方案**：
  - 接入层：LangChain4j 1.0.1-beta6 声明式 `@AiService`（`AiChatAssistant`，`@SystemMessage` 设定"资深住宅装修设计师"角色，非装修问题礼貌拒绝）；模型为百炼 **qwen3-vl-plus** 视觉模型，走 OpenAI 兼容协议，复用 `BAILIAN_API_KEY`。
  - 分层：Controller（DataURL 解析 + 四分支入参校验）→ `AiChatService`（异常转译）→ `AiChatAssistant`（框架生成代理，自动组装 `TextContent + ImageContent`）。
  - 图片格式：前端 `FileReader` 转 DataURL 提交 JSON；后端从 `data:{mime};base64,{数据}` 解析 MIME 与 base64，`ImageContent.from(base64, mimeType)` 入模。**本地开发不能传 localhost URL（云端模型拉不到）**。
  - 稳定性：限流(429)/超时/上游 5xx/网络不可达统一转业务码 503 友好提示；Key 错误/欠费(401/403)不转译、原样暴露；框架自带自动重试（1.0.1 默认首发 + 最多 2 次重试，指数退避约 0.5s/0.75s + 抖动）。
- **多轮记忆（AI-3，✅ 已完成，本期仅纯文本链路）**：
  - 原理：大模型本身无状态，"记忆"= 每轮请求时把该会话的历史消息重新拼入；滑动窗口只保留最近 **10 条**（约 5 轮问答，SystemMessage 不占名额），超出自动淘汰最老消息，控制 token 成本。
  - 组件：`ChatMemoryProvider`（`AiConfig` 装配 `MessageWindowChatMemory`，窗口 10）+ 自研 `RedisChatMemoryStore`（implements ChatMemoryStore，消息经 LangChain4j `ChatMessageSerializer` 序列化为 JSON 存 Redis）；`@AiService` 方法以 `@MemoryId` 标注会话 id，框架自动取历史、拼新问题、回写问答。
  - 会话 id：首轮请求不带，后端生成 UUID 并通过响应返回，前端后续轮次原样带回。**memoryId 由服务端用 `UserContext` 组装为 `{userId}:{conversationId}`，Redis 实际键为 `ai:memory:{userId}:{uuid}`——归属段不信任客户端传入，传他人会话 id 读不到任何历史（IDOR 防护）；conversationId 必须匹配 UUID 格式白名单，非法返回 400「非法会话标识」**。
  - 存储：Redis 持久化（2026-09-27 由内存 Map 升级，commit 866588b），TTL 24h（`app.ai.memory-ttl-seconds=86400`，每次写回续期），服务重启不丢、多实例可共享；窗口淘汰仍由 `MessageWindowChatMemory` 在内存侧保证。
  - 图文链路（裸 ChatModel）本期不接记忆，后续需手工"取历史拼入 + 调完回写"。
- **验收**：
  1. 纯文本提问可得到装修领域回答；非装修问题被礼貌拒绝；
  2. 只发图片（无文字）时 AI 默认按"请解释这张图"解读；
  3. 文+图同时提交，回答能结合图片内容（风格/颜色/材质识别正确）；
  4. 双空提交返回 400；模型繁忙时返回 503 友好文案而非 500；
  5. 同一会话连续追问（AI-3 完成后）能引用上文上下文，新会话互不干扰。
  6. **（AI-3 专项）**首轮不带 conversationId，响应返回新生成的 id；同一会话追问"那大概多少钱"这类指代词时，AI 能结合上文正确作答；
  7. **（AI-3 专项）**不同 conversationId 的上下文互不串扰；连续对话超过 10 条后，最老的消息不再被引用（窗口淘汰生效）；记忆持久化在 Redis（24h TTL，重启后 TTL 内仍承接上下文）；传入他人的 conversationId 读不到历史消息，传入非 UUID 格式的伪造会话标识返回 400（2026-10-12 已实测归属隔离）。
- **接口契约**：见接口文档 §11（`POST /api/ai/chat`、§11.3 多轮记忆）。

### 10.5 手机验证码登录（A-10，2026-09-21 新增，✅ 2026-09-22 完成，⛔ 2026-10-21 下线）

> **下线说明（2026-10-21）**：短信签名受运营商实名制报备政策阻塞（个人认证无法申请），真实环境用户收不到验证码，Mock 通道无演示价值。随手机号注册/登录功能整体下线，相关代码（`SmsService`/`MockSmsServiceImpl`/`SmsCodeService`/`loginByPhone` 等）、配置（`app.sms.*`/`SMS_PROVIDER`）、`t_user.phone` 列与 `sms:*` Redis 键全部清除。以下为历史详设存档，仅供追溯。

- **目标**：用户无需密码，凭手机号 + 短信验证码即可登录，降低注册/登录门槛；手机号首次验证通过即自动完成建档。
- **角色与入口**：未登录用户在登录页（`Login.vue`）通过顶部切换选择「手机登录」，与现有账号密码登录并列，复用同一双栏杂志风布局。
- **业务规则**：
  1. 仅支持大陆 11 位手机号（正则 `^1[3-9]\d{9}$`）；验证码为 6 位随机数字。
  2. **发送间隔 60 秒**：间隔内重复点击直接拒绝并提示剩余秒数（前端按钮倒计时 + 后端 Redis 频控双保险，以后端为准）；后端用 SETNX 原子占位，并发双击只发送一条。**发码前按场景预检**（请求带 `scene=login/register`）：登录页对未注册手机号、注册页对已注册手机号直接返回对应提示且不发短信、不占频控，用户可立即切换页面重试。
  3. **验证码 5 分钟内有效**：过期需重新获取；验证码**一次性**——登录成功立即作废。
  4. 验证码错误或过期统一提示「验证码错误或已过期」，不区分具体原因（防信息探测）；输错不销毁验证码，允许在有效期内重试。
  5. **每日发送总量上限（2026-10-12 新增）**：同一手机号 10 条/24h、同一 IP 20 条/24h，超限 429，接真实短信通道前的资损防护。
  6. **注册与登录入口分离（2026-10-12 调整）**：注册只有统一入口 `/api/auth/register`，必填用户名（3-32）、手机号、短信验证码、密码（8-32，BCrypt 存储）；用户名与手机号均做唯一校验（预检 + 唯一索引并发兜底），注册成功前端自动登录。`/sms/login` 仅面向已注册手机号，未注册返回「该手机号未注册，请先注册」，登录接口不负责建档。
  7. 登录成功与账号密码登录一致：签发 JWT（7 天有效），前端保存 token 并拉取用户信息后跳转。
- **技术方案**：
  - 复用已接入的 Redis（`StringRedisTemplate` + `RedisAtomicCounter` 公共原子计数器）。四类 key：`sms:code:login:{phone}`（验证码本体，TTL 300s）、`sms:limit:login:{phone}`（发送频控标记，TTL 60s，SETNX 原子占位）、`sms:daily:phone:{phone}` 与 `sms:daily:ip:{ip}`（24h 发送计数，固定窗口 86400s，阈值 10/20）；键设计见数据库设计文档「Redis 键设计」。
  - 短信通道定义 `SmsService` 接口，本期提供 Mock 实现：验证码只打印后端日志、不随接口返回；后续接阿里云/腾讯云短信时仅替换实现，接口契约不变。通道发送失败时删除 60 秒占位允许用户立即重试（日计数不回滚）。
  - TTL/阈值参数配置化：`app.sms.code-ttl-seconds=300`、`resend-interval-seconds=60`、`daily-phone-limit=10`、`daily-ip-limit=20`、`daily-window-seconds=86400`。
- **验收标准**：
  1. 合法手机号点「获取验证码」返回成功，后端日志可见 6 位验证码，按钮进入 60 秒倒计时；
  2. 60 秒内再次发送被拒绝（前端拦截 + 后端 429）；并发双击仅成功一条且不消耗日额度；
  3. 输入正确验证码：已注册手机号登录进入系统，未注册手机号收到「未注册，请先注册」提示（引导至注册页）；`redis-cli` 确认登录后验证码 key 已删除；
  4. 验证码错误/过期/未获取均返回 400「验证码错误或已过期」；同一验证码第二次使用失败；
  5. 非法手机号格式、空验证码等参数校验返回 400；
  6. 切换 Tab 不影响两种登录方式各自的表单状态与校验；
  7. 同手机号第 11 次/24h、同 IP 换号第 21 次/24h 均返回 429（2026-10-12 已实测）。
- **明确不做（后续加固）**：验证码错误尝试次数上限（当前 `sms:fail:login` 5 次锁定已实现）、自然日零点重置的日窗口（当前为 24h 固定窗口）、真实短信通道、手机账号后续补设密码（与 A-5 一并设计）。
- **接口契约**：见接口文档 §2.6（发送验证码）、§2.7（验证码登录）。

### 10.6 邮箱注册与验证码登录（A-11，2026-10-15 新增，✅ 2026-10-17 完成；2026-10-21 手机通道下线后成为唯一注册/登录验证通道）

- **背景**：个人认证账号无法通过运营商短信签名实名制报备（阿里云 2025-06 政策），短信验证码无真实可用通道；邮箱 SMTP 发信免费、无需资质，作为真实可用的注册/登录通道。2026-10-21 手机通道下线后，邮箱成为账号体系唯一的联系标识。
- **目标**：用户可凭邮箱 + 邮件验证码完成注册与免密登录。
- **角色与入口**：
  - 登录页（`Login.vue`）：「账号登录 / 邮箱登录」两个 Tab（邮箱 + 6 位验证码）。
  - 注册页（`Register.vue`）：邮箱注册表单（用户名、邮箱、验证码、密码、确认密码）。
- **账号体系**：
  1. `t_user` 以 `email VARCHAR(128)` + 唯一索引 `uk_email` 作为联系标识（2026-10-21 手机通道下线时 `phone` 列与 `uk_phone` 索引已删除）。
  2. 注册时邮箱必填：邮箱走邮件验证码校验；用户名、密码仍必填且规则不变。
  3. 本期不做邮箱 + 密码登录（账号登录仍只认用户名）。
- **业务规则**：
  1. 邮箱格式后端正则校验（RFC 简化正则：`^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$`，长度 ≤ 128）；验证码为 6 位随机数字。
  2. **发送间隔 60 秒**：SETNX 原子占位 `email:limit:login:{email}`，并发双击只发一封；前端按钮 60 秒倒计时，以后端频控为准。
  3. **发码前按场景预检**：`scene=login` 邮箱必须已注册、`scene=register` 邮箱必须未注册，不符直接 400 且不发信、不占频控。
  4. **验证码 5 分钟有效、一次性**：`email:code:login:{email}` TTL 300s，登录/注册校验成功立即删除；校验失败保留，允许有效期内重试。
  5. **每日发送上限**：同邮箱 10 封/24h、同 IP 20 封/24h（`email:daily:email/ip`，固定窗口 86400s），超限 429。
  6. **验证码输错 5 次锁定**：`email:fail:login:{email}` 计数 300s，复用登录限流组件通用计数方法。
  7. 邮箱注册成功前端自动登录（注册后以用户名 + 密码走账号登录）；邮箱验证码登录仅面向已注册邮箱，未注册返回「该邮箱未注册，请先注册」，登录接口不负责建档。
  8. 登录成功签发 JWT（7 天有效），前端保存 token 并拉取用户信息后跳转，与其他登录方式完全一致。
- **技术方案**：
  - `spring-boot-starter-mail`：Spring Boot 自动装配 `JavaMailSender`，用 `MimeMessage` + `MimeMessageHelper` 发送 HTML 邮件（UTF-8）；QQ 邮箱 `smtp.qq.com:465` SSL，连接/读超时各 5s 防线程挂死；发信同步调用，失败删除 60s 占位允许立即重试。
  - `EmailService`（发信通道接口）+ `EmailServiceImpl`；`EmailCodeService`（复用 `StringRedisTemplate` / `RedisAtomicCounter` / `LoginRateLimiter`）。
  - 凭证外部化：`MAIL_USERNAME`（发件邮箱）/ `MAIL_PASSWORD`（**QQ 邮箱授权码，非登录密码**）环境变量注入；`MAIL_HOST` 默认 `smtp.qq.com`、`MAIL_PORT` 默认 465；prod 下账号/授权码无默认值，缺失即启动失败。
  - TTL/阈值独立配置块 `app.email.*`（300/60/10/20/86400）。
- **验收标准**：
  1. 未配置 `MAIL_USERNAME/MAIL_PASSWORD` 时本地启动不失败，仅发码接口报错（邮件非核心启动依赖）；prod 缺失两者启动失败（fail-fast）。
  2. 注册页：合法邮箱点「获取验证码」真实收到 HTML 邮件，邮件内含 6 位验证码且 5 分钟有效提示；按钮进入 60s 倒计时；60s 内重发被前后端双重拒绝。
  3. 邮箱注册全链路：验证码校验 → 用户名/邮箱占用预检 → 建档（email 落库）→ 自动登录进入项目页。
  4. 已注册邮箱在注册场景发码返回 400「该邮箱已注册，请直接登录」；未注册邮箱在登录场景返回 400「该邮箱未注册，请先注册」，均不发信、不占频控。
  5. 邮箱验证码登录：正确码进入系统且验证码 key 立即删除；错误/过期/未获取统一 400；连续错 5 次 429；同一验证码二次使用失败。
  6. 频控：同邮箱第 11 封/24h、同 IP 换邮箱第 21 封/24h 返回 429。
  7. 账号密码登录回归无影响；两个登录 Tab 表单状态互不干扰。
- **明确不做（边界）**：邮箱 + 密码登录、邮箱绑定/换绑/解绑、找回密码（A-6）、邮件退订链接。
- **接口契约**：见接口文档 §1.1（注册）、§1.6（发送邮箱验证码）、§1.7（邮箱验证码登录）。

### 10.7 修改密码（A-5，2026-10-17 新增并实现；2026-10-21 手机通道随手机号功能下线）

- **目标**：已登录用户凭本人绑定邮箱收到的验证码修改密码；不使用原密码（验证码即身份凭证）。
- **角色与入口**：登录后进入「设置」页（`Settings.vue`）的修改密码卡片；页面加载时通过 `/api/auth/me` 获取掩码后的绑定信息（`maskedEmail` 如 `3***@qq.com`），邮箱通道仅对已绑定邮箱的用户可用；未绑定邮箱（理论不存在）提示联系管理员。
- **业务规则**：
  1. 发码前校验通道归属：`channel=email` 必须有 email，未绑定返回 400 且不发信；收件地址**永远由后端按当前登录 userId 查库决定，绝不接受前端传入的邮箱**（防用他人验证码改自己密码）。
  2. **60 秒发送间隔**：`pwd:limit:{userId}` SETNX 原子占位。
  3. **每日上限 10 次/24h**：`pwd:daily:{userId}` 固定窗口 86400s。
  4. **验证码 5 分钟有效、一次性、按通道隔离**：`pwd:code:email:{userId}` TTL 300s；改密成功立即删除；错误保留允许有效期内重试。
  5. **验证失败 5 次锁定**：`pwd:fail:{userId}` 计数 TTL 300s，第 5 次起 429「验证码错误次数过多，请重新获取验证码」；重新发码与改密成功时清零。
  6. 新密码规则同注册：8–32 字符；本期**不校验**新旧密码是否相同（2026-10-17 决策）。
  7. **改密成功当前 token 立即拉黑**：复用 JWT 黑名单（`jwt:blacklist`），前端收到成功响应后本地清登录态并跳登录页，须用新密码重新登录；其他端持有的旧 token 同样在过期前失效。
  8. 发送通道：email 走 `EmailService`（QQ SMTP 真实发信）。
- **技术方案**：`common/PasswordChangeService`（发码 + 校验改密），复用 `RedisAtomicCounter` 与 `LoginRateLimiter` 的通用验证码失败计数方法；Redis key 独立 `pwd:*` 前缀，与登录/注册验证码场景隔离（避免越场重放）；阈值配置块 `app.password-change.*`（300/60/10/86400）。
- **验收标准**：
  1. 未绑定邮箱请求 400；发码成功真实收信，60s 倒计时与后端 429 双保险。
  2. 正确验证码 + 合法新密码 → 改密成功，当前 token 随后请求 401；用新密码账号登录成功，旧密码登录失败。
  3. 验证码错误/过期统一 400，同一码二次使用失败；连续错 5 次返回 429，重新发码后可再试。
  4. 第 11 次发码/24h 返回 429；伪造邮箱参数无效（后端不读取该参数）。
- **接口契约**：见接口文档 §1.8（发送改密验证码）、§1.9（提交修改密码）；§1.3 `/me` 响应掩码字段。

### 10.8 账号设置 · 邮箱绑定与换绑（2026-10-17 新增并实现；2026-10-21 手机栏随手机号功能下线移除）

- **目标**：账号设置页（`Settings.vue`）承载邮箱绑定状态展示、邮箱绑定/换绑、修改密码三块。
- **页面结构**：
  1. 邮箱栏：未绑定显示「未绑定」+「绑定邮箱」按钮；已绑定显示掩码（如 `3***@qq.com`）+「更换邮箱」按钮；点击弹出对话框输入新邮箱 → 获取验证码 → 提交。
  2. 修改密码卡片：沿用 §10.7，不改动。
- **业务规则**：
  1. 全程登录态；绑定/换绑**只需新邮箱验证码**（2026-10-17 决策：登录态即身份证明，不做旧邮箱二次验证）。
  2. 新邮箱在发码前与提交时**两次占用校验**：已被任意账号绑定返回 400「该邮箱已被其他账号绑定」，不发信、不占频控；并发下由 `uk_email` 唯一索引兜底（捕获 `DuplicateKeyException`）。
  3. 频控独立 `bind:email:*` key（按 userId 归属）：60s 发送间隔、10 次/24h、验证码 5 分钟有效且一次性、输错 5 次锁 300s（复用 `LoginRateLimiter` 通用计数方法）。
  4. 绑定/换绑只更新 `t_user.email`，不影响密码、昵称；成功后前端重新拉取 `/me` 刷新掩码。
  5. 邮箱格式/长度走 DTO 校验（与注册同款正则，≤128）。
- **技术方案**：`common/EmailBindService`（发码 + 绑定确认），复用 `EmailService`、`RedisAtomicCounter`、`LoginRateLimiter`；新增两个 DTO 与两个鉴权接口；配置块 `app.email-bind.*`（300/60/10/86400）。
- **验收标准**：
  1. 未登录调绑定接口 401；未绑定时发码到新邮箱真实收信，正确验证码绑定成功，`/me` 的 maskedEmail 立即更新；
  2. 用已被占用的邮箱（如其他注册用户的邮箱）发码/提交均 400，不发信；
  3. 换绑后用新邮箱可走「邮箱验证码登录」与「邮箱改密」；旧邮箱可被重新用于注册；
  4. 60s 重发 429、错码 5 次 429、验证码二次使用失败。
- **接口契约**：见接口文档 §1.10（发送绑定邮箱验证码）、§1.11（确认绑定/换绑邮箱）。
