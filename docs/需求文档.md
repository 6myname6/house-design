## 1. 产品概述

### 1.1 背景与目标
面向装修业主与设计师，提供"上传房屋设计图 → AI 生成可交互 3D 施工效果 → 社区分享交流"的一站式可视化平台。核心目标是让用户在施工前就能身临其境地预览装修完成效果，降低决策与沟通成本。

### 1.2 价值主张
- 零门槛出图：上传一张图即可生成写实效果图。
- 可交互漫游：3D 场景支持旋转/缩放/平移/自动环视。
- 风格可换：内置 5 种主流装修风格。
- 生成直连智谱：单厂商直连，直接调用智谱 CogView 文生图（无内置 mock 兜底）。
- 社区互动：装修灵感沉淀与分享。

### 1.3 技术栈
Spring Boot 3 + MySQL 8 + Vue 3 + Three.js + 智谱 CogView；本地文件系统存储。登录限流使用 Redis（已实现，见 S-3）；AI 多模态对话使用 LangChain4j 接入智谱 glm-4.6v-flash（见 §3.7 / §10.4）。

## 6. 关键业务流程

### 6.1 核心闭环
```
注册/登录 → 新建项目(传图+选风格) → 发起生成(异步) → 轮询状态
→ 查看 3D 效果 → (可选)社区发帖/浏览/点赞/评论
```

### 6.2 生成状态机
```
PENDING ──► PROCESSING ──► SUCCESS
                  │
                  └──────► FAILED (errorMessage 记录原因)
```
失败原因需覆盖：智谱 429 限流（指数退避重试）、额度不足、Key 无效、`ZHIPU_API_KEY` 未配置等，均写入 `errorMessage`（无 Key 直接报错提示，不回退 mock）。

## 7. 验收标准（本期交付基线）

1. 单用户可完整走通"上传→生成→查看→分享"闭环。
2. 未登录访问受保护接口返回 401，前端自动登出。
3. 用户仅能访问自己的资源，越权返回 403/404。
4. 上传文件被类型与大小校验拦截非法文件。
5. 列表接口支持分页且不随数据量线性劣化。
6. 密钥不落库、不进版本库（已通过环境变量 + .gitignore 约束）。

## 10. 新增需求（2026-09-14）

> 本节登记上一轮迭代后的前端新需求，均处于「规划中 ⬜」状态，验收标准随实现补充。

### 10.1 登录页背景轮播（A-8）

- **目标**：提升登录/注册页品牌感与视觉吸引力。
- **行为**：页面背景展示 5 种装修风格效果图（两张以上可轮播），每 **5 秒**自动切换一张；登录表单悬浮于背景之上，确保可读性。
- **素材**：效果图来源待定（可复用生成模块产出的 panoramaUrl / 静态资源目录），切换时建议淡入淡出过渡。
- **验收**：登录页加载后背景自动轮播，5 秒间隔稳定；切换动画流畅；表单区域不遮挡。

### 10.2 帖子详情页（C-12）

- **目标**：社区内容可"点开详读"，完整展示互动数据。
- **行为**：
  - 「我的发布」列表点击某条帖子 → 进入帖子详情页（`/posts/:id`）；
  - 详情页展示：作者、时间、正文、图片、点赞数、评论数、评论区（全部评论与该帖回复）；
  - 本人与他人均可对帖子和评论点赞、发表评论/回复（复用装修小圈评论区既有交互与接口）。
- **后端**：需补充**单帖详情接口**（按 id 返回 PostResponse，含归属校验/404 防枚举）；评论列表复用 `GET /api/posts/{postId}/comments`。
- **验收**：从「我的发布」点击可进入详情；他人点赞/评论可见；本人点赞/评论即时生效并回显。

### 10.3 左侧导航栏收起/展开（N-8）

- **目标**：大屏幕下为内容区让出更多空间。
- **行为**：侧边栏头部提供折叠按钮；收起后仅显示图标（或品牌 Logo），导航文字隐藏，内容区自动变宽；展开恢复原状。
- **粒度**：仅前端布局调整（`TabBar`/根布局），不涉及路由。
- **验收**：点按钮可收起/展开且状态平滑切换；收起态下导航项仍可点击并保持高亮。

### 10.4 AI 设计助手：多模态对话（AI，2026-09-18 新增）

- **目标**：用户可向 AI 咨询装修问题（风格识别、配色、建材、预算等），并能**发送图片**让 AI 结合画面回答（如"这张图是什么风格""我家户型能不能这样装"）。
- **技术方案**：
  - 接入层：LangChain4j 1.0.1-beta6 声明式 `@AiService`（`AiChatAssistant`，`@SystemMessage` 设定"资深住宅装修设计师"角色，非装修问题礼貌拒绝）；模型为智谱 **glm-4.6v-flash** 视觉模型，走 OpenAI 兼容协议，复用 `ZHIPU_API_KEY`。
  - 分层：Controller（DataURL 解析 + 四分支入参校验）→ `AiChatService`（异常转译）→ `AiChatAssistant`（框架生成代理，自动组装 `TextContent + ImageContent`）。
  - 图片格式：前端 `FileReader` 转 DataURL 提交 JSON；后端从 `data:{mime};base64,{数据}` 解析 MIME 与 base64，`ImageContent.from(base64, mimeType)` 入模。**本地开发不能传 localhost URL（云端模型拉不到）**。
  - 稳定性：限流(429)/超时/上游 5xx/网络不可达统一转业务码 503 友好提示；Key 错误/欠费(401/403)不转译、原样暴露；框架自带 3 次指数退避重试。
- **多轮记忆（AI-3）**：`ChatMemoryProvider` 按 `conversationId` 维护 `MessageWindowChatMemory`（滑动窗口保留近期消息）；首轮无 id 由后端生成，后续轮次带回；起步内存 Map，后续可换 Redis 持久化。
- **验收**：
  1. 纯文本提问可得到装修领域回答；非装修问题被礼貌拒绝；
  2. 只发图片（无文字）时 AI 默认按"请解释这张图"解读；
  3. 文+图同时提交，回答能结合图片内容（风格/颜色/材质识别正确）；
  4. 双空提交返回 400；模型繁忙时返回 503 友好文案而非 500；
  5. 同一会话连续追问（AI-3 完成后）能引用上文上下文，新会话互不干扰。
- **接口契约**：见接口文档 §11（`POST /api/ai/chat`）。
